# Проверка темпа уровней — RIKITU

**Утверждённые ориентиры:** 6–8 минут на обычный уровень, 8–10 минут на
уровень с мини-боссом, 10–15 минут при тщательном исследовании.

## Два принципиально разных показателя

1. `scripts/pacing_audit.py` проверяет геометрию всех существующих уровней
   (по 3 фрагмента, 90 монет, 3 контрольные точки, 4 секции, мини-босс на
   каждом чётном) и считает **условное время прямого горизонтального
   пробега** от старта к выходу при штатной скорости бега. Оно **не измеряет
   реальную длительность игрового прохождения**, не гарантирует достижимость
   такого пробега и не проверяет удовольствие от игры.
2. Для проверки настоящих 6–8 / 8–10 минут необходимо пройти уровни
   обычным управлением — без `RIKITU_TEST_MOVE` — с обязательным поиском трёх
   фрагментов. После прохождения игра сохраняет время, повреждения и монеты
   в журнале результатов. Зафиксируйте результаты нескольких попыток.

## Запуск проверки геометрии

```bash
python -m pip install playwright==1.57.0
python -m playwright install chromium
python scripts/pacing_audit.py --output pacing-audit.json
```

JSON содержит исходные ширины, положение выхода, имена четырёх секций,
штатную скорость, номинальное время прямого движения и целевой диапазон.
GitHub Actions выполняет этот аудит отдельно и сохраняет JSON как артефакт.

**Правило:** не корректировать длину уровня только по номинальному
пробегу. Приоритет — реальные игровые действия, простые механики,
исследование, секреты и комфортное возвращение к пропущенному фрагменту.
